# 庭のキャンバス｜Garden Canvas

植えて、眺めて、入れ替えて。理想の庭を見つけよう。

公開URL: https://nature-wx-lab.github.io/garden-canvas/

## 試作 0.2 の範囲

同じ庭を3Dで眺めながら、植物・季節・将来サイズ・購入予算・手入れを試す庭プランニングツールです。サーバーへの庭データ送信はありません。

- 実寸の外周（長方形・L字・自由多角形）、複数の花壇、多角形で近似する円形花壇、建物・通路・塀。幅・奥行き2〜30m、外周32頂点、花壇12区画、外構16個。外構は軸に沿う長方形です。
- 10種・品種の植物カタログ。各植物に成株寸法、開花期、生育や手入れの参考情報と出典を表示。葉形、枝、花穂・花房、落葉、冬の種子頭をコードで描き分けます。
- 個体ごとの追加・移動・複製・固定・削除・交換プレビュー。交換は採用／取消が可能です。案AからBを複製し、同じカメラ・月・経過年数で比較できます。最大100株／案、編集を40回まで戻す／やり直す。
- 季節と計画開始からの年数を別々に指定。個体の植える日、初期の高さ・株幅・葉高と、利用者が入力した将来の寸法を連動させます。草の株幅に応じて葉・茎の数も変わります。
- 剪定直後の寸法、自然な枝姿／外周を整える表現、回復月数を試せます。登録した剪定・切り戻しの月を予定表と3Dが共用。幹の構造を縮める目標は未対応として表示します。
- 新規購入株の入力単価を積み上げ、未入力数を併記。既存株・参考配置は除外します。初期サイズ変更時は価格と成長・剪定寸法を解除し、古い見積りを流用しません。
- 月別の手入れ、初年度のみの作業、所要時間の幅、水やり回数、月ごとに使える時間。準備・片付けは作業のある月に1回加算する利用者設定。時間超過でも作業は勝手に削除しません。
- 条件に合う植物候補から配置または交換を試せます。開花の参考、株幅の重なり、外周・外構への張り出しを表示します。美しさや栽培可否の採点ではありません。
- JSONで案・個体・予定・視点を保存・復元。0.1の保存ファイルも読めます。旧版の4形状は種類未指定のまま保持し、実在品種へ勝手に読み替えません。

## 成長・手入れ・3Dの限界

**年次成長の予測、必要な剪定頻度、実写品質、外部AIアシストは完成していません。** 資料で確認できる成株寸法や「成株到達2〜5年」から、年ごとのサイズや管理回数を推定できるとは扱いません。

年次数値未設定の植物は初期サイズを保ちます。利用者が将来寸法と年数を入力した場合だけ、初期状態との間を直線補間し、設定年以降は固定する計画シナリオです。これは種別の生物学的成長曲線ではありません。別モードの「資料の成株上限」は資料の寸法上限を示し、指定年の予測や剪定後の姿と混ぜません。

剪定後の回復も入力した月数による直線的な仮定です。芽吹き・花芽形成・強剪定による樹勢低下・病害虫・根の競合・地域気候は計算していません。剪定予定が未登録なら寸法目標だけで剪定は起きません。予定表0件は手入れ不要を意味しません。実際に必要な作業の網羅性・頻度・所要時間は未検証です。

開花月・成株寸法は海外資料の参考値です。一般化した冬季を12〜2月、紅葉を10〜11月とする描画であり、日本各地の実測時期ではありません。植物表現は手続き的な参考3Dです。全株の健康な生育、花数、正確な枝ぶり、実写品質を保証しません。

交換は「最初から別種を植えた計画」の比較です。元個体の座標・植える日を保持し、新種の仮の初期寸法に戻し、旧種の価格・成長・管理設定を解除します。将来の特定日に旧株を抜き新株へ替える履歴、曲線の直接編集、区画の穴、一括移動、地図・写真の取込みは未実装です。

## 操作と保存

1. 「庭をつくる」で外周・寸法、花壇、外構を用意します。寸法変更では配置と外構の平面寸法も伸縮します。固定株があるときや外周から植物・区画がはみ出す変更は受け付けません。
2. 「植える」で植物を選び、庭をクリックします。初期サイズは仮の配置入力で、販売苗の規格ではありません。「眺める・選ぶ」で配置モードを終了します。
3. 植物をクリックまたは一覧から選び、寸法、価格、将来サイズ、手入れを調整して「反映」を押します。資料は各植物の欄にあります。
4. ドラッグで回転、ホイール／2本指で拡大・移動。「全体」「真上」「目線」「寄って見る」で視点を戻せます。左右矢印でも回転、Escapeで形の編集等を解除します。
5. Bに複製するとAを残して比較できます。個体交換もプレビューしてから採用します。案を切り替えても視点・季節・経過年数を保持します。
6. 「保存」で `garden-canvas-plan-v2.json` を端末へ書き出し、「開く」で復元します。画面を閉じる・再読込する前に保存してください。自動保存・クラウド保存はありません。

保存形式はversion 2、modelVersion `scenario-1`、catalogVersion `2026-10-09.1`。読込は3MBまで、個体・区画・作業件数、有限数値、範囲、未知項目、重複ID、外周内包含を検査します。不正なファイルは元の庭を保持したまま拒否します。手入れ予定は1株36件まで、表示年は0〜10年です。

## プライバシーと公開境界

庭は画面のメモリーだけに保持し、再読込するとサンプルへ戻ります。住所・位置情報・写真・ログインは取得しません。庭を共有URL、サーバー、アクセス解析、外部AIへ送る機能はありません。保存ファイルには庭の寸法・配置・価格・予定が含まれるため、利用者自身で管理してください。配信元GitHubには通常のHTTPアクセス情報が届きます。

描画ライブラリを同梱し、外部CDN・フォント・計測タグは読み込みません。Content Security Policyのmeta指定で外部通信、埋込み、フォーム送信等を制限します。GitHub Pagesではアプリが任意のHTTPセキュリティヘッダーを設定できず、metaはHTTPヘッダーの完全な代替ではありません。フレーム埋込み制限はこの配信方式では保証しません。秘密情報やクラウド保存の追加には別途設計が必要です。

専用の独立リポジトリを配信元とし、`site/` 内の許可した12ファイルだけをPages artifactに含めます。公開ソース19ファイルと全到達可能コミットのファイル・氏名・メール・メッセージを `scripts/release_check.py` で検査。許可外ファイル・個人メール形式・ローカルパス・主要な資格情報形式は配信を停止します。未知の秘密や全個人情報を静的検査で完全検出できるものではなく、差分の目視確認も必要です。

author・committerは `nature-wx-lab` と確認済みGitHub noreplyを使用し、個人のGit既定値を継承しません。Actionsは検査時に読み取り権限だけ、配信ジョブにPages用の権限だけを付与します。Actionsは固定commitを参照し、独自の長期認証情報は不要です。

## 開発と検証

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory site
node --test scripts/model.test.mjs
python3 scripts/release_check.py
```

変更はこの専用リポジトリで行い、許可ファイルだけを明示的にstageします。公開更新の依頼を確認し、UI検証とリリース検査後にmainへpushするとActionsが検査・配信します。モデル検査は旧版互換、入出力境界、時間軸・剪定イベント、費用未入力、作業時間、区画・外構を対象とします。ローカル／公開の代表操作、PC／スマートフォン、配信12ファイルのbytes、配信commit、Content-Type、404も確認します。
