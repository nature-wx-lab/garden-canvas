# 庭のキャンバス｜Garden Canvas

植えて、眺めて、入れ替えて。理想の庭を見つけよう。

公開URL: https://nature-wx-lab.github.io/garden-canvas/

## 正本と収録方針

本READMEが、Garden Canvasの目的・収録方針・実装上の判断・公開契約を所有する唯一の説明正本です。個々の植物の事実はデータファイル、実装はコード、特定リリースの確認結果は検証成果物が所有します。同じ植物台帳や進捗台帳を別の文書へ複製しません。実行版は `package.json`、カタログ版は `site/catalog-data.js`、公開中の版は実際の配信ファイルとActionsを照合します。

- 対象は屋外の庭。庭木・宿根草・一年草・カラーリーフ・球根植物・バラ・クリスマスローズ・クレマチス・多肉・水生植物の10ジャンルを扱います。約3,000件は目安であり、件数合わせの架空品種・重複追加はしません。大きくなる桜・カツラ・クスノキ等も、成株寸法を隠さず含めます。
- 利用者提供資料は植物名だけを参照し、価格・説明・画像・その他の列を転用しません。室内観賞中心の植物は対象外です。白鳥（サボテン）、アデニウム・ブラック、寿光、ディソアンシーは除外指定を維持します。
- ドライガーデンは、関東など冬に霜が降りる平地での地植え越冬を基準にします。多肉・アガベという分類だけでは採用せず、種類ごとの耐寒性、排水、冬の雨などの条件を出典とともに扱います。全国一律の越冬保証ではありません。除外した旧カタログの保存個体は読込時に消しません。
- 人気順は店舗と掲載時点を区別します。園芸ネットの草花・庭木各300件と、おぎはら植物園の公開週間ランキングの収録情報を使い、現在の全国人気順位とは呼びません。バラは品種に加えて花色タイプでの収録も許容しますが、確認済みの花形・樹姿の違いは保持します。

現在のデータは2,946件です。これは収録数であり、写実的な年間再現の完成数ではありません。収録を変更したときは実データから再集計します。

## ツールの範囲

同じ庭を3Dで眺めながら、植物・季節・将来サイズ・購入予算・手入れを試す庭プランニングツールです。サーバーへの庭データ送信はありません。

- 実寸の外周（長方形・L字・自由多角形）、複数の花壇、多角形で近似する円形花壇、建物・通路・塀。幅・奥行き2〜30m、外周32頂点、花壇12区画、外構16個。外構は軸に沿う長方形です。
- 名前・別名・ジャンル・花色・樹形・資料・人気順・ドライガーデン条件で検索する植物カタログ。確認できた成株寸法、開花期、形態と出典を表示。葉形、枝、花穂・花房、落葉、冬の種子頭をコードで描き分けます。外観未対応や混合種は明示し、既知の種へ勝手に置き換えません。
- 個体ごとの追加・移動・複製・固定・削除・交換プレビュー。交換は採用／取消が可能です。案AからBを複製し、同じカメラ・月・経過年数で比較できます。最大100株／案、編集を40回まで戻す／やり直す。
- 季節と計画開始からの年数を別々に指定。個体の植える日、初期の高さ・株幅・葉高と、利用者が入力した将来の寸法を連動させます。草の株幅に応じて葉・茎の数も変わります。
- 剪定直後の寸法、自然な枝姿／外周を整える表現、回復月数を試せます。登録した剪定・切り戻しの月を予定表と3Dが共用。幹の構造を縮める目標は未対応として表示します。
- 新規購入株の入力単価を積み上げ、未入力数を併記。既存株・参考配置は除外します。初期サイズ変更時は価格と成長・剪定寸法を解除し、古い見積りを流用しません。
- 月別の手入れ、初年度のみの作業、所要時間の幅、水やり回数、月ごとに使える時間。準備・片付けは作業のある月に1回加算する利用者設定。時間超過でも作業は勝手に削除しません。
- 条件に合う植物候補から配置または交換を試せます。開花の参考、株幅の重なり、外周・外構への張り出しを表示します。美しさや栽培可否の採点ではありません。
- JSONで案・個体・予定・視点を保存・復元。0.1の保存ファイルも読めます。旧版の4形状は種類未指定のまま保持し、実在品種へ勝手に読み替えません。

## 見た目と動き

イロハモミジは専用の葉と枝構造を使用します。汎用の細長い葉から、7つの裂片が放射状に広がる掌状葉、細かな鋸歯、放射状の葉脈へ変更。葉柄で小枝につながる対の葉、横へ分かれる枝、葉群の間の隙間を描きます。[NC State Extensionの樹形・葉の資料](https://plants.ces.ncsu.edu/plants/acer-palmatum/)を形態の参考にしています。実木のスキャンや品種固有の精密モデルではありません。入力寸法を保つ専用の参考モデルで、年次成長の仮定は変更していません。

曲面の葉と花びら、細い枝・花茎、葉脈や樹皮の陰影、個体内の色の揺らぎを追加しました。風は株元を固定し、枝先のしなりと葉の細かな動きを組み合わせます。同じ変形を影にも適用します。芝・土は実素材の色と法線マップに小さな立体形状を重ねています。

風は「なし／そよ風／やや強め」、光は「日中／夕方」で切り替えられます。実際の風速・日照の計算ではありません。動きを減らす端末設定では風なしで開始し、非表示・画面外では描画を休止。通常最大30fps、40株超では最大24fpsとし、多数の植物は細部の密度を落とします。配置個体は省略しません。風と光は鑑賞用設定で、保存JSONの内容には含めません。

## 成長・手入れ・3Dの限界

**年次成長の予測、必要な剪定頻度、実写品質、外部AIアシストは完成していません。** 資料で確認できる成株寸法や「成株到達2〜5年」から、年ごとのサイズや管理回数を推定できるとは扱いません。

年次数値未設定の植物は初期サイズを保ちます。利用者が将来寸法と年数を入力した場合だけ、初期状態との間を直線補間し、設定年以降は固定する計画シナリオです。これは種別の生物学的成長曲線ではありません。別モードの「資料の成株上限」は資料の寸法上限を示し、指定年の予測や剪定後の姿と混ぜません。

剪定後の回復も入力した月数による直線的な仮定です。芽吹き・花芽形成・強剪定による樹勢低下・病害虫・根の競合・地域気候は計算していません。剪定予定が未登録なら寸法目標だけで剪定は起きません。予定表0件は手入れ不要を意味しません。実際に必要な作業の網羅性・頻度・所要時間は未検証です。

開花月・成株寸法は国内外の種苗元・販売元・植物園等の一次資料に基づく参考値です。資料の地域、露地・温室、品種・種の区別を保持します。日本の月を海外の月から機械的に決めず、地域差や資料間の違いを説明します。資料にない月境界・残葉率・寸法比は描画上の近似であり、各項目の未確認欄へ残します。

冬に地上部がなくなる宿根草、冬も葉を保つ種類、秋播き一年草、夏休眠する種類を分けます。落葉樹の冬枝は残し、草本の休眠では葉・花茎等の地上部を必要に応じて消します。一年草は開花後に終了し、翌秋に同じ個体が自動復活しません。再播種は別株として追加します。開花月が不明であることを「開花しない」「休眠する」と読み替えません。

植物表現は手続き的な参考3Dです。葉の形・模様・裏面、枝の出方、幹と樹皮、花冠・花弁・萼・花序は種類別に実装を進めていますが、全株の健康な生育、花数、正確な枝ぶり、実写品質を保証しません。

### 完成の判定と資料の所有

`site/appearance-data.js` の `status` は `unconfirmed`（細部資料未確認）、`attributes`（資料属性を登録）、`partial`（個別の形態・季節を部分実装）の3段階です。`partial` は写実的再現の完成ではありません。全件分の記録があること、有限な形状を描けること、12か月のテストが通ることも、実物との一致を証明しません。実物同等と検証済みの件数は現時点で0件で、要求全体は未完了です。

植物ごとの出典URL・適用範囲（品種／種／属）・各形態の根拠・未確認事項を同じレコードへ置きます。資料写真は形態の観察に使い、転載許諾がない画像を公開資産へ複製しません。属の特徴や写真から置いた値を、品種の実測値へ格上げしません。品種名を同定できないものは候補を分け、断定しないで他の作業を進めます。

判定には、出典の実物と全形・葉・枝・花を見比べること、冬・展葉期・開花期・花後の整合、月別モデルの検査、実際の公開画面の確認が必要です。モデル件数を増やすだけで完了扱いにせず、平板な葉、規則的すぎる枝、寸法比や密度の不自然さも残件にします。掲載写真が不足する月の姿は未検証のまま明示します。

交換は「最初から別種を植えた計画」の比較です。元個体の座標・植える日を保持し、新種の仮の初期寸法に戻し、旧種の価格・成長・管理設定を解除します。将来の特定日に旧株を抜き新株へ替える履歴、曲線の直接編集、区画の穴、一括移動、地図・写真の取込みは未実装です。

## 操作と保存

1. 「庭をつくる」で外周・寸法、花壇、外構を用意します。寸法変更では配置と外構の平面寸法も伸縮します。固定株があるときや外周から植物・区画がはみ出す変更は受け付けません。
2. 「植える」で植物を選び、庭をクリックします。初期サイズは仮の配置入力で、販売苗の規格ではありません。「眺める・選ぶ」で配置モードを終了します。
3. 植物をクリックまたは一覧から選び、寸法、価格、将来サイズ、手入れを調整して「反映」を押します。資料は各植物の欄にあります。
4. ドラッグで回転、ホイール／2本指で拡大・移動。「全体」「真上」「目線」「寄って見る」で視点を戻せます。左右矢印でも回転、Escapeで形の編集等を解除します。
5. Bに複製するとAを残して比較できます。個体交換もプレビューしてから採用します。案を切り替えても視点・季節・経過年数を保持します。
6. 「保存」で `garden-canvas-plan-v2.json` を端末へ書き出し、「開く」で復元します。画面を閉じる・再読込する前に保存してください。自動保存・クラウド保存はありません。

保存形式はversion 2、modelVersion `scenario-1`。catalogVersionは実装内の現行値を使い、既存の版から個体ID・案・利用者の入力を保って移行します。読込は3MBまで、個体・区画・作業件数、有限数値、範囲、未知項目、重複ID、外周内包含を検査します。不正なファイルは元の庭を保持したまま拒否します。手入れ予定は1株36件まで、表示年は0〜10年です。

## プライバシーと公開境界

庭は画面のメモリーだけに保持し、再読込するとサンプルへ戻ります。住所・位置情報・写真・ログインは取得しません。庭を共有URL、サーバー、アクセス解析、外部AIへ送る機能はありません。保存ファイルには庭の寸法・配置・価格・予定が含まれるため、利用者自身で管理してください。配信元GitHubには通常のHTTPアクセス情報が届きます。

描画ライブラリを同梱し、外部CDN・フォント・計測タグは読み込みません。Content Security Policyのmeta指定で外部通信、埋込み、フォーム送信等を制限します。GitHub Pagesではアプリが任意のHTTPセキュリティヘッダーを設定できず、metaはHTTPヘッダーの完全な代替ではありません。フレーム埋込み制限はこの配信方式では保証しません。秘密情報やクラウド保存の追加には別途設計が必要です。

専用の独立リポジトリを配信元とし、`scripts/release_check.py` の `SITE` に列挙した25ファイルだけをPages artifactに含めます。公開リポジトリの許可対象は `ALLOWED` の36ファイルです。これらと全到達可能コミットのファイル・氏名・メール・メッセージを同検査で確認します。許可外ファイル・個人メール形式・ローカルパス・主要な資格情報形式は配信を停止します。未知の秘密や全個人情報を静的検査で完全検出できるものではなく、差分の目視確認も必要です。

author・committerは `nature-wx-lab` と確認済みGitHub noreplyを使用し、個人のGit既定値を継承しません。Actionsは検査時に読み取り権限だけ、配信ジョブにPages用の権限だけを付与します。Actionsは固定commitを参照し、独自の長期認証情報は不要です。

## 開発と検証

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory site
npm test
python3 scripts/release_check.py
```

変更はこの専用リポジトリで行い、許可ファイルだけを明示的にstageします。親ワークスペースや作業用フォルダをまとめてstageしません。公開更新の依頼を確認し、UI検証とリリース検査後にmainへpushするとActionsが検査・配信します。公開直前の検査には `--publish-request`、`--preview-verified`、`--target nature-wx-lab/garden-canvas` を渡します。検査中は対象の追跡ファイルを変更しません。

変更した形態・季節の代表例と境界例を先に検査し、CIで既存のモデル・カタログ・樹木・形態テストを実行します。検証範囲は変更に比例させ、過去の全画像・全データを理由なく作り直しません。新しいデータ項目には許可スキーマと範囲検証を加えます。葉数・花器・月別状態のテストと、実物との視覚照合は別の工程です。

ローカル実装、ローカル確認、push、Actions配信、公開ファイル一致、公開画面確認を分けて報告します。公開ファイルは通常URLのbytesと配信対象commitの `git show <SHA>:site/...` を比べます。手元に次版の変更がある場合、作業ツリーのbytesで公開版を判定しません。PCとスマートフォンの代表操作・季節変化を確認し、表示崩れやコンソールエラーを記録します。

接写では、小さな葉に対して影の範囲と深度バイアスが大きすぎると、葉同士の影が消えて平板に見えます。風の頂点変形と深度描画は揃え、日中・夕方、樹木・草花・水面、近景・全体表示を必要な範囲で確認します。カメラや選択を変えた直後の古いフレームを新しい結果と誤認しないよう、選択状態を読んでから描画画像を確認します。

長期作業は週の利用枠を節目で読み取り、残量0％を確認したら停止します。リセット権は使用しません。残量は他作業と共有され、定期確認による停止はクレジット消費ゼロの保証ではありません。ユーザーが移行・一時停止を指定した場合は、元の長期目標を停止し、移行先の初回依頼の範囲を守ります。

## 出典と依存

植物名・検索属性・基本出典は `site/catalog-data.js`、形態の根拠と未確認事項は `site/appearance-data.js` が所有し、`site/catalog.js` が組み合わせます。樹木の樹形は `site/tree-profiles.js`、年間状態は `site/catalog-search.js` と `site/model.js`、個別形状は `site/plant-detail.js`、材質・形状の組立ては `site/vegetation.js`、木の枝は `site/tree-model.js`、照明・カメラ・地面は `site/scene.js` を確認します。資料URLと確認日は画面にも表示します。植物は独自の手続き的3Dで、地面にはPoly HavenのCC0素材を同梱しています。

- [NC State Extension Plant Toolbox](https://plants.ces.ncsu.edu/)
- [Missouri Botanical Garden Plant Finder](https://plantfinder.mobot.org/)
- [RHS 植物資料](https://www.rhs.org.uk/plants)

地面の色・OpenGL法線マップは [Leafy Grass](https://polyhaven.com/a/leafy_grass)（Charlotte Baglioni、実寸幅2m）と [Brown Mud 02](https://polyhaven.com/a/brown_mud_02)（Rob Tuytel、幅1.3m）の1K JPEGです。[Poly HavenのCC0ライセンス](https://polyhaven.com/license)で再配布し、元画像は改変していません。4枚合計約4.6MB。元URL・作者・SHA-256を `asset-lock.json` に固定し、画像の差し替えも公開検査の対象にします。実行時にPoly Havenへ接続することはありません。
